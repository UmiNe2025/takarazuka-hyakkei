## 3. 自動更新の仕組み(¥0・GitHub Actions 週次)

### 本日修正済み(commit 95cdfbe)
- **取得確認日(fetched)と本文変更日(changed)を分離**。従来は毎週 fetched が動き、内容が同じでも全ページの dateModified/lastmod がビルド日に塗り替わっていた(Google が lastmod を信用しなくなる典型)。今は内容差分がある時だけ changed が進み、カテゴリ単位で lastmod に反映(現状: 6/13×7、9/21×2、9/22×4)。
- **添付ファイル名の変更に追従**。市は再アップロードのたびにファイル名を変える(20260210.xlsx → matikadokoukyou20260730.xlsx)。AED と赤ちゃんの駅は 7/27 から 404 で古いデータのままだった → 掲載ページから .xlsx リンクを解決する方式に変更し 171件/108件を復元。

### 設計原則
1. **1検索意図=1固定URL**。町名×施設×日付のページ展開はしない(おやこみちの1,878ページ削除の教訓)。自動更新は固定URL内の「節」を更新する。
2. 表示は「取得確認日 / 原典更新日 / 本文変更日」を分けて出す。取得失敗時は前回値+取得日を残し「最新」と言わない。
3. 公式に記載のない設備は「不明」と書く。SVG に未確認の段差・通路を描かない。
4. 自動更新は鮮度が必要なクエリ(イベント・休館)でのみ評価される。順位上昇の保証はない。
