# くらしの便利帳 デザイン改善仕様(/designspec)

作成: 2026-07-06 / 対象: `/life/`(宝塚くらしの便利帳) / 目的: 「最新技術でリッチ」を **¥0静的 × 厳格CSP × 全年齢アクセシビリティ** と両立させる実装直前仕様。

> **誠実性の前提**: 以下の ux/brand/技術/コスト の視点は Opus によるペルソナ的統合であり、実在の専門デザイナー/フォントベンダーのレビューの代替ではありません。最終判断はプロの確認を推奨します。単一視点の次元には「単一視点・要専門確認」を明記します。

## Phase 0: 前提(自走文脈のため確定回答なし → 文脈から確定・要検証)

| 問 | 置いた前提(要検証) |
|---|---|
| ブランド性格 | 信頼できる公共性 × すみれの街の情緒。派手さより「困ったときに早く届く安心」 |
| ターゲット | 宝塚市の住民全般。**高齢者・子育て世帯・不慣れな人を含む**。緊急/おくやみ等ストレス下の利用も多い |
| 言語・市場 | 日本語主。外国人相談導線あり(多言語は市公式へ委譲)。RTL・高伸長言語なし → 国際化次元は昇格しない |
| 参考・避けたいトーン | 避: 広告的・チカチカ・情報過多。参: 行政UD/自治体DX の「静かで確実」なトーン |

## Phase 1: 方向性 3案 → 推奨1案(自走のためフォールバック選択・理由明記)

- **A. 「静かな役所窓口」UD最優先案** — UDフォント+高コントラスト+装飾最小。モーションはほぼ無し。最も堅実・最も退屈。
- **B. 「すみれの手帖」情緒×実用案(推奨)** — UDフォントで可読性を担保しつつ、すみれ紫の面・和のリズム・微細なモーションで「宝塚の手帖」らしさを出す。リッチさと落ち着きの両立。
- **C. 「カード大胆リッチ」案** — 大きな色面・ガラス質(backdrop-filter)・スクロール連動アニメ多用。最も"今風"だが、高齢者・緊急利用・低速端末にリスク。

**推奨 = B**。理由: 対象に高齢者・ストレス下利用を含むため C の刺激過多はリスク、A では「宝塚百景の姉妹サイト」らしい情緒が死ぬ。B は **UD可読性(実用)× すみれの情緒(ブランド)** を両立し、"リッチ"を装飾でなく「質感・余白・微細な動き・ダークモード」で表現する。mood=静謐で品がある/配色=すみれ紫の面+和紙の地+カテゴリ色の細差し/タイポ=UDゴシックの明快さ+見出しにわずかな明朝の格/レイアウト骨格=カード+余白広め/情緒=「ちゃんと守られている」。

## Phase 3: 決定的次元(タイポ/配色/UI実装)— 具体値+実行時ゲート

### 3-1. タイポグラフィ

**改善の核 = 本文にユニバーサルデザイン書体「BIZ UDPGothic」を採用。** UD書体は行政・全年齢・弱視の可読性向けに設計され、生活ガイドの利用文脈に直接効く。

| 用途 | 書体 | ウェイト | 配信 | ライセンス |
|---|---|---|---|---|
| 本文・UI(生活ガイド) | **BIZ UDPGothic** | 400/700 | Google Fonts + `font-display:swap` + `preconnect`済 | SIL OFL 1.1(webfont+商用可)[事実(出典: Morisawa/Google Fonts)] |
| 見出しの格・サイトブランド | Zen Old Mincho | 600/700 | 既に site全体で読込済 | SIL OFL 1.1 [事実(出典: Google Fonts)] |
| (代替) 現行維持 | Zen Kaku Gothic New | 400/500/700 | — | SIL OFL 1.1 |

- **和文容量対策**: 日本語webfontは重い。**`unicode-range`サブセットは行わず**(動的生成の常用漢字が不定のため)、Google Fonts の最適化配信+`font-display:swap`に委ねる。BIZ UDPGothicは2ウェイトに絞りZen Kaku(3ウェイト)から差し替えれば**正味の追加DLは実質増えない**。
- 流体サイズ: `font-size: clamp(15px, 0.9rem + 0.3vw, 17px)`(本文)。見出しは`clamp()`で階層化。行間 1.8(和文可読)。
- [推定(UD書体の設計目的に基づく)] 高齢者・弱視の可読性が向上。[仮説(要検証: 実機での高齢者テスト1件)] 実際の読了率改善。

### 3-2. 配色システム(すべて実測 [事実(算出: sRGB相対輝度)])

**現行の要修正2件(実測で確認):**
- `--ink-faint #708185` = 本文4.5に対し **3.76:1 FAIL** → **`#5c6d71`(5.01:1 PASS)** に変更
- `--gold #c98732` を明るい地の文字に使うと **2.78:1 FAIL** → 文字用に **`--gold-text #8a6122`(5.10:1 PASS)** を新設。`--gold`は大面・装飾・暗地限定に用途固定

**ダークモード(新規・`light-dark()`で実装、Baseline 2024):**

| トークン | Light | Dark | Darkの実測 |
|---|---|---|---|
| paper(地) | #f3f7f5 | **#16232a** | — |
| card | #ffffff | **#1e2f37** | — |
| ink(本文) | #203238 (12.34:1) | **#e8eef0** | **13.70:1 PASS** |
| ink-soft | #4b5d62 (6.39:1) | **#b9c6ca** | **9.17:1 PASS** |
| ink-faint | #5c6d71 (5.01:1) | **#8fa0a5** | **5.92:1 PASS** |
| 見出し(sumire) | #5d467d (7.37:1) | **#c9b3e0** | **8.42:1 PASS** |
| gold(見出し装飾・大文字3:1) | — | #f1bb58 | **9.17:1 PASS** |

- カテゴリ12色は**Lightでは白文字ボタンとして全AA合格(実測)**。Darkではカード上に「色文字」で出すため**明度を上げた dark 変種**を用意し実測合格を確認(例: garbage `#a6c483`=7.15:1、procedure `#b79ce6`=5.87:1、medical `#6fc4b8`=6.77:1、emergency `#f08a76`=5.67:1、tax `#e0c070`=7.87:1、events `#e6b45f`=7.29:1、いずれも on #1e2f37)。**残る6カテゴリ色のdark変種は実装時に同式で算出**([要検証]: 未算出の6色)。
- **[事実]ガードの注記**: 上記は**solid同士**の実測値。半透明パネル・グラデ地・SVG上のテキストは最悪合成色での下限を別途算出するか`[要検証]`に落とす(単一hex値を[事実]として流用しない)。
- 実装: `color: light-dark(var(--ink-l), var(--ink-d))` を各トークンに。`color-mix()`で面のトーン差(`color-mix(in oklab, var(--c-medical) 12%, var(--card))`等)を作り、ハードコード色を減らす。

### 3-3. UI実装方針(「最新技術」の正体 = CSSネイティブ)

**設計判断: 静的¥0 × CSP script-src厳格 という制約下では、重いJSフレームワークは不適。逆に2024–2026のCSSネイティブ機能が最適解** — inline JS/ハンドラ不要でCSPに一切触れず、"リッチ"を実現できる。

| 技術 | 用途 | CSP/¥0適合 | フォールバック |
|---|---|---|---|
| **View Transitions**(`@view-transition{navigation:auto}`) | カテゴリ間遷移を滑らかに(文脈維持) | CSSのみ・JS不要 | 非対応は通常遷移(無害) |
| **Container Queries**(`@container`) | カードが置かれた幅で自律レイアウト | CSSのみ | 幅メディアクエリに縮退 |
| **`:has()`** | 「保存済カードを含む列だけ強調」等の状態表現をJSレスで | CSSのみ | 効かないだけ(無害) |
| **Scroll-driven Animations**(`animation-timeline:view()`) | 項目の控えめな出現 | CSSのみ | 静止表示(無害) |
| **`light-dark()` / `color-mix()` / `clamp()`** | ダークモード・トーン・流体 | CSSのみ | — |
| **`backdrop-filter`** | SOS/検索バーの軽いガラス質(任意・控えめ) | CSSのみ | 不透明背景に縮退 |
| 既存 life.js(許可済ハッシュ) | 検索・あとで見る(localStorage) | 現状維持 | — |

- **FW選定**: 推奨=**現行の静的生成(prerender-life)を維持**し、CSSのみ強化。代替=Astro等の静的FW導入だが、現行が¥0で回っており**KISS原則で不採用**(個人・静的・CSP厳格の案件に重装備は過剰)。CSS方針=既存 life.css のトークンを拡張(命名互換)+`@layer`で優先度整理。
- トレードオフ: View Transitions/scroll-driven は Safari の一部旧版で未対応 → **プログレッシブエンハンスメント前提**(無くても機能は完全)。

### 3-4. 実行時ゲート(devil-advocate 1回)→ **要修正→再通過で合格**

- 攻撃「緊急/おくやみ等ストレス下の利用に、リッチな装飾・モーションは有害では?」→ **妥当な指摘**。修正: **SOS・緊急・おくやみ導線は View Transition/scroll演出の対象外**とし、常に即時・最高コントラスト・アニメ非ブロッキング。`prefers-reduced-motion:reduce`で全モーション停止を必須化。
- 攻撃「BIZ UDPGothic 追加はDL増でLCP悪化では?」→ Zen Kaku(3w)をBIZ UDP(2w)へ差替えで**正味増やさない**方針で回避。
- 攻撃「ダークモードのカテゴリ色、6色未算出を"対応済"と誤認させないか?」→ 6色は`[要検証]`と明記し実装時算出を必須化。
- 判定: **合格(要修正2点を反映済)**。

  - UI: 現行静的生成維持+CSSネイティブ(View Transitions/Container Queries/:has/scroll-driven/light-dark/color-mix)。JSはlife.jsのみ。
- **素材**: 追加写真なし(制約)。カテゴリSVGアイコンの線幅・角丸統一(点数=12、自作、権利クリア)。生成要時は/genprompt。
- **AAチェック**: 本文・補助・見出し・ボタン=**実測PASS**。要修正2件は改善値で**PASS**。ダーク主要トークン=**PASS**。※コントラスト比のみ機械保証。フォーカス/SR/キーボードはux所見どまり=**実機A11y検証を推奨**。
- **実装接続(→/mission契約の入力粒度)**:
  1. life.css `:root`にlight/dark2値トークン+`light-dark()`化(命名互換で差分最小)
  2. `@font-face`ではなくGoogle Fonts link差替(Zen Kaku→BIZ UDPGothic)。prerender-life.mjsのhead生成を1箇所修正

  6. SOS/緊急/おくやみは演出除外の明示クラス
- **未解決前提と最安検証**:
  - [要検証] ダークのカテゴリ残6色 → **同式Bashで即算出**(コスト0/5分)
  - [要検証] BIZ UDPGothic導入の高齢者可読性/LCP実測 → **PageSpeed 1回+知人1名の実機確認**(コスト小)
